# Pathname non-contiguous block batch overwrite

`write_file_blocks_at_path_journaled` exposes the existing format-v5 `write_file_blocks_journaled` primitive through bounded absolute-path resolution. Before resolving the pathname, it recovers and checkpoints any older committed WAL so intermediate and final symbolic-link resolution is derived from recovered durable namespace state. The resolved inode ID is then delegated to the existing durable batch-overwrite implementation.

The operation atomically replaces any non-empty set of distinct, already-existing logical blocks in one regular file. The logical indices do not need to be contiguous. It does not allocate or free blocks, change inode references, alter namespace metadata, extend the file, create holes, or define byte-length/EOF/extent semantics. Filesystem format remains v5.

Durability of the batch overwrite remains in the inode-level primitive: all changed data-block images are emitted in one WAL transaction, committed transactions are replayed to home locations, and the fixed journal reservation is checkpointed before successful return. Invalid batches are rejected before overwrite WAL publication. Because pathname resolution now begins with recovery, the first call after a crash may also replay an older committed namespace transaction and clear its journal before resolving the target.

The existing pathname crash matrix enumerates every injected write/flush interruption in the overwrite itself and requires recovery to expose either the complete old batch or the complete new batch, never a mixed result. The dedicated recovery-boundary test separately enumerates every crash point while creating a committed target symlink, reboots without external recovery, invokes the pathname batch overwrite through that alias, and verifies recovered namespace selection, complete overwritten data, allocator/inode accounting, unique allocator-owned physical references, fsck cleanliness, an empty checkpointed journal, and idempotent second recovery.
