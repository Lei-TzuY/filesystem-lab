# Bounded symbolic links

Filesystem format v5 supports bounded symbolic-link lifecycle operations through inode-record codec v2. The filesystem superblock and inode-record versions do not change in this slice because symlink target payloads are independently self-identifying and existing `SYM1` images remain readable without migration.

`create_symlink_journaled` creates a new `Symlink` inode under an existing directory and stores one non-empty UTF-8 target string in newly allocated data blocks. The target is opaque filesystem data: creation does not resolve it, require that it exists, or distinguish relative from absolute paths.

Targets that fit in one block retain the historical payload version: magic `SYM1`, a 16-bit payload version, a 16-bit byte length, an IEEE CRC-32 field, UTF-8 target bytes, and zero-filled trailing bytes. This preserves byte-for-byte compatibility for the existing one-block representation.

Longer targets use the independently identified `SYM2` representation. The first block carries magic `SYM2`, a 16-bit payload version, reserved zero bytes, a 32-bit total target length, and an IEEE CRC-32 over the complete UTF-8 target bytes. Target bytes then continue contiguously across the inode's ordered block vector and all unused bytes in the final block must be zero. The representation is bounded to `MAX_SYMLINK_TARGET_BLOCKS` (8) and therefore cannot grow without bound or consume an unbounded WAL transaction.

Allocator ownership, the new symlink inode, the new namespace entry, and every target block image are published by one WAL transaction. A crash before durable commit must preserve the old state. A crash after durable commit may expose a prefix of home writes, but recovery must converge to the complete new state before the journal is checkpointed and reused. There is no valid mixed state in which namespace, inode ownership, allocator accounting, target block count, or target data disagree.

`read_symlink` accepts either one-block `SYM1` or bounded `SYM2`. `SYM1` must reference exactly one block. `SYM2` validates its block count against the encoded total length, rejects unsupported versions or non-zero reserved/trailing bytes, validates the complete-target CRC and UTF-8, and returns the opaque target string. An empty symlink block vector or one exceeding the bounded limit is corruption.

`hard_link_symlink_journaled` can add another namespace alias to an existing validated symlink inode without changing allocator ownership, the inode image, or target data. `unlink_nonfinal_symlink_link_journaled` removes exactly one alias while another durable reference remains. `unlink_symlink_journaled` removes the final namespace reference, validates the complete target payload, verifies ownership of every referenced target block, frees all of those blocks, and removes the inode and selected directory entry. Their mutation paths retain deterministic crash/recovery coverage and read-only fsck agreement.

`resolve_path_following_symlinks` adds a bounded read-only lookup surface. It accepts absolute paths rooted at inode 1, traverses directory entries component by component, and follows persisted `Symlink` inodes through `read_symlink`. Absolute symlink targets restart lookup from root; relative targets restart from the directory containing the symlink; any remaining suffix is preserved after expansion. Lookup follows at most `MAX_SYMLINK_EXPANSIONS` (40) links and rejects longer chains or loops. Missing components report `NotFound`; corrupted namespace/inode/symlink data continues to surface as consistency errors. A multi-block target is still subject to the same pathname parser and symlink-expansion limits when it is followed.

Pathname traversal now interprets `.` and `..` as executable directory components rather than rejecting them lexically. `.` leaves lookup at the current directory. `..` resolves the unique persisted namespace parent of the current directory; inode 1 is clamped to itself so repeated attempts to walk above root remain at root. For non-root directories, missing or multiply referenced parentage is reported as `InvalidData` instead of selecting an arbitrary parent. These rules apply equally to direct absolute paths and to relative or absolute symlink targets expanded during traversal. Empty components and trailing slashes on non-root paths remain rejected.

`resolve_path_without_following_final_symlink` uses the same traversal contract for intermediate components but returns the final namespace inode without expanding it when that inode is a symlink. This makes the symlink inode itself addressable even when its opaque target is dangling. A final symlink followed by `.` or `..` is necessarily an intermediate component and is expanded before the dot component is evaluated. `read_symlink_at_path` first recovers and checkpoints any older committed WAL, then runs that no-follow-final lookup and validates the final symlink payload through `read_symlink`, providing bounded pathname-level `readlink` semantics against recovered durable namespace state. Intermediate symlinks are still expanded and count toward the same 40-link limit; the final symlink is not expanded merely to identify or read it.

The low-level pathname lookup helpers remain read-only. Pathname `readlink` does not create a new WAL transaction or change filesystem format v5, but its first call after a crash may replay and checkpoint an older committed transaction before resolving the requested symlink. Dedicated recovery-boundary regressions require recovered namespace selection, allocator/inode accounting, unique physical ownership, clean fsck, an empty checkpointed journal, and idempotent second recovery.

Final unlink does not erase freed target blocks' old bytes. Once allocator ownership is released those blocks are no longer reachable filesystem data and may be reused by later allocation.

This slice intentionally does not implement current-working-directory lookup, trailing-slash directory semantics, permission checks, FUSE integration, or general POSIX compatibility.
